🗑️ Garbage Collection & Closures

The Namaste 🙏 JavaScript example. Two variables are born together — the closure saves one, the garbage collector silently deletes the other. You'll catch V8 in the act.

The code

function a() {
  var x = 0,
      z = 10;
  return function b() {
    debugger;           // browser pauses here
    console.log(x);     // b uses x… but NEVER uses z
  };
}

var y = a();   // a() finishes — what survives in b's closure?
y();

✅ x — KEPT

b references it → reachable → the closure keeps it alive.

🗑️ z — GARBAGE COLLECTED

Nobody references it → V8 freed its memory the moment a() returned. It's not "undefined" — it's gone.

▶ Run the experiment

1️⃣ Open DevTools first: press F12 (required — debugger only pauses when DevTools is open)
2️⃣ Click the button below → the browser freezes inside b
3️⃣ Look at the Scope panel (right side of the Sources tab): Closure (a) → x: 0 … and no z anywhere!
4️⃣ Still paused, switch to the Console tab and type: x → prints 0 ✅   then z → ReferenceError: z is not defined ❌
5️⃣ Press F8 to resume
Nothing happened? DevTools must be open before you click. Press F12, then click again.

🔬 The proof — one reference rescues z

Same code, but this version of b contains one extra line: console.log(z). Now b uses z, so the closure must keep it. Run it, and this time the Scope panel shows Closure (a2) → x: 0 AND z: 10 — and typing z in the Console prints 10. 

return function b() {
  debugger;
  console.log(x);
  console.log(z);   // ← the ONE line that saves z from the garbage collector
};

The lesson: closures don't blindly keep the whole outer scope. V8 scans the inner function and keeps only the variables it actually references — everything else is garbage-collected immediately. Memory is freed by unreachability: no reference = no mercy. 🗑️
