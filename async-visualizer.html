⏱ main-thread heartbeat: 0.00s clock stops moving = JavaScript is frozen

⏳ Callbacks → Promises → async/await

JavaScript itself is synchronous: one call stack, one thing at a time. The browser does the waiting (timers, network). Callbacks, promises and async/await are three ways of writing the same thing: "browser, call my code back when it's done." Watch the heartbeat clock at the top the whole time.

1Proof: waiting in JavaScript freezes everything

Both buttons wait 3 seconds. The red one waits inside JavaScript with a busy loop. The green one hands the waiting to the browser with setTimeout and a callback. Click each, and while it waits, watch the heartbeat clock and try clicking "click me anytime". 

// ❌ synchronous wait: JavaScript itself is busy for 3s
const end = Date.now() + 3000;
while (Date.now() < end) {}          // the one call stack is occupied

// ✅ asynchronous wait: the browser waits, JavaScript is free
setTimeout(() => log("done"), 3000);   // callback = "call this when done"
→ try both and watch the clock
Notice with the red button: even the "starting…" log line only appears after the 3 seconds. Drawing the screen also needs the main thread, so the page can't even update while JavaScript is busy. That's why JavaScript never waits for slow work itself; it hands the work off and asks to be called back.

2One task, three styles: user → orders → invoice

Three fake server calls, each taking 800ms, and each needing the previous result. The same job is written three ways. Run each one and compare the timestamps; they behave identically. Keep clicking "click me anytime" while they run: the page never freezes.

① Callbacks

getUser(7, (err, user) => {
  if (err) return fail(err);
  getOrders(user, (err, orders) => {
    if (err) return fail(err);
    getInvoice(orders[0], (err, inv) => {
      if (err) return fail(err);
      done(inv);
    });
  });
});
// pyramid 🔺 + error check at EVERY level

② Promises

getUser(7)
  .then(user => getOrders(user))
  .then(orders => getInvoice(orders[0]))
  .then(inv => done(inv))
  .catch(err => fail(err));
// flat chain ➡ + ONE .catch for all steps

③ async / await

async function run() {
  try {
    const user   = await getUser(7);
    const orders = await getOrders(user);
    const inv    = await getInvoice(orders[0]);
    done(inv);
  } catch (err) { fail(err); }
}
// reads top-to-bottom like sync code,
// but never freezes the page
Look at the first lines of each log: the "returned instantly" message always appears at ~0ms, before any result. In every style, JavaScript starts the work, moves on immediately, and gets called back later. Run all three at once: they finish together, because all three were waiting in the browser in parallel.

3Proof: promises are callbacks in a nicer package

On this page, only the callback versions of the three functions were written by hand. The promise versions used by styles ② and ③ were generated from them with this small helper, a higher-order function using a closure (tabs 1 and 6): 

const promisify = (fn) => (...args) =>      // HOF: callback-style fn in, promise-style fn out
  new Promise((resolve, reject) => {
    fn(...args, (err, data) =>            // still calls the ORIGINAL callback function…
      err ? reject(err) : resolve(data));  // …and turns its callback into resolve/reject
  });

const getUser    = promisify(getUserCb);
const getOrders  = promisify(getOrdersCb);
const getInvoice = promisify(getInvoiceCb);

So under styles ② and ③ there is still a callback being called by setTimeout. The promise just receives it and passes the result on to your .then. And await is built on .then: the rest of the async function after each await is resumed through the microtask queue once the promise settles. 

callback  →  wrapped in a promise  →  consumed with .then  →  or with await
(what the browser calls)   (resolve/reject)   (you attach)    (looks like waiting, isn't)
Try it in the Console (F12): type getUser(7) and press Enter. You get Promise {<pending>} immediately. Run await getUser(7) and after 800ms you get the user object.
