🎯 this · call · apply · bind

Inside a regular function, this is decided by HOW the function is called — not where it's written. call / apply / bind let YOU choose it. Watch the 🎯 jump between objects below.

1The problem: this follows the caller

One function, two ways to call it, two different this. The 🎯 marker shows who this points at for each call: 

const person = {
  name: "Vivek",
  intro() { console.log("Hi, I am " + this.name); }
};
person.intro();              // this = person  (called as a method)
const loose = person.intro;  // same function, taken out of the object…
loose();                     // this = undefined 💥 (called alone)

2call & apply — run NOW with the this you choose

fn.call(obj, a, b) and fn.apply(obj, [a, b]) are identical except how arguments are passed: Call = Commas, Apply = Array. The function doesn't belong to either object — we lend it a this per call ("function borrowing"): 

function intro(city, country) {
  console.log(`I am ${this.name} from ${city}, ${country}`);
}
const vivek = { name: "Vivek" };
const akshay = { name: "Akshay" };

intro.call(vivek, "Delhi", "India");      // commas
intro.apply(akshay, ["Mumbai", "India"]); // array

vivek

{ name: "Vivek" }

akshay

{ name: "Akshay" }
→ same function, any this you want

3bind — lock this for LATER

bind runs nothing. It returns a new function whose this is permanently locked. No matter who calls it later — a button, a timer, anyone — this can't be lost anymore: 

const boundIntro = intro.bind(vivek);  // nothing runs — a new function is returned
boundIntro("Delhi", "India");         // this = vivek, forever 🔒

// even passed to setTimeout (which calls it as "nobody"):
setTimeout(boundIntro, 1000, "Delhi", "India");  // still Vivek! ✓
→ do steps 1, 2, 3 in order, then the red comparison
bind = closure + HOF! You can build it yourself with what you already know:
function myBind(fn, obj) { return (...args) => fn.apply(obj, args); }
The returned function keeps obj in its 🎒 backpack — exactly like debounce keeps timerId. (Classic interview question: "polyfill bind".)

Real-world uses: fixing this in callbacks/event handlers (the #1 use), function borrowing (Array.prototype.slice.call(arguments) in old code), Math.max.apply(null, arr) before spread syntax existed, and partial application (const double = multiply.bind(null, 2)).

Modern note: arrow functions don't have their own this — they inherit it from where they're written (like a closure over this!). That's why arrows + spread syntax replaced many call/apply/bind uses. But interviews still love all three.
