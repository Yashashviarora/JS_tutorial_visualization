🌐 fetch — watch it in DevTools

The Namaste JavaScript example. Press F12 first and keep DevTools open, then run the steps in order. Each step shows the same fetch from a different DevTools panel.

1fetch returns a Promise immediately (Console)

const GITHUB_API = "https://api.github.com/users/akshaymarch7";

const user = fetch(GITHUB_API);
console.log(user);                 // what is `user` at THIS moment?
  1. Open the Console tab, then click the button.
  2. The first line printed is Promise {<pending>}. The data doesn't exist yet; the request has only just been sent.
  3. Now click the ▸ arrow to expand that same logged promise. It shows [[PromiseState]]: "fulfilled". It changed after it was logged, because Chrome shows the object's current state when you expand it.
  4. 1.5 seconds later the page logs the promise again: now even the collapsed line says fulfilled.

2The request itself (Network tab)

  1. Switch to the Network tab, then click the button.
  2. A row named akshaymarch7 appears. That's the request the browser made for you, outside JavaScript.
  3. Click the row: Headers shows the URL, method (GET) and status (200); Response shows the raw JSON the server sent; Timing shows where the time went (connecting, waiting for the server, downloading).
  4. Notice the Console tab's log lines appear while the request is still in the Network list as pending: JavaScript didn't wait for it.

3Set your own breakpoints (Sources tab)

const user = fetch(GITHUB_API);              // breakpoint A
user.then(function (data) {
  console.log(data);                          // breakpoint B (inside .then)
});
console.log("button handler finished…");      // breakpoint C
  1. Open the Sources tab. In the left file tree, open 127.0.0.1:5500 → fetch-devtools.js. (Or press Ctrl+P and type fetch-devtools.)
  2. Find the STEP 3 block and click the line numbers of the three lines marked breakpoint A, B and C. A blue marker appears on each.
  3. Click the Step 3 button. Before you resume, guess the order the three breakpoints will be hit in. Press F8 to go from one to the next.
  4. At A: user doesn't exist yet. Press F10 (step over) once and look at user in the Scope panel: Promise {<pending>}.
  5. At B: expand data in Scope. It's a Response object (status: 200, ok: true), but no user data yet; the body hasn't been read. Also look at the Call Stack panel: the button click handler isn't there. It finished long ago, and this callback was started later by the event loop as a microtask.
  6. Click the blue markers again to remove them when you're done.

4Getting the actual data: a second promise

fetch(GITHUB_API)
  .then((response) => response.json())   // reading the body is ALSO async → another promise
  .then((data) => {
    console.log(data.name, data.followers);
    showCard(data);
  })
  .catch((err) => console.error("failed:", err));

Why two .thens? The first promise settles when the headers arrive. The body may still be downloading, so response.json() returns another promise that settles once the whole body is read and parsed. Returning it from the first .then makes the chain wait for it.

5Errors: 404 does NOT reject, network failure does

  1. Click "404 user": it asks for a user that doesn't exist. The Network tab shows a red 404, but the Console shows the promise was fulfilled, with ok: false. fetch only rejects when no response arrives at all.
  2. To see a real rejection: in the Network tab, change "No throttling" to "Offline", then click "offline test". Now .catch runs with TypeError: Failed to fetch. Switch back to "No throttling" afterwards.
const res = await fetch(url);
if (!res.ok) throw new Error("HTTP " + res.status);   // you must check this yourself
Rate limit: GitHub allows about 60 unauthenticated requests per hour per IP. If you start getting status 403, wait a while before trying again.
